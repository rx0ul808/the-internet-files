THE INTERNET FILES / INVESTIGATION 001

THE DAY META
WENT DARK.

On October 4, 2021, some of the world's most widely used online platforms suddenly became inaccessible. What happened, and how did a network configuration failure affect millions of people?

FILE #001 OCTOBER 4, 2021 DIGITAL HISTORY DOCUMENTED CASE
01 / CASE OVERVIEW

What happened?

On October 4, 2021, Facebook, Instagram, WhatsApp and other Meta services experienced a widespread global outage lasting several hours.

Users around the world were unable to reliably access the affected services. The outage also disrupted Meta's internal systems, making it more difficult for engineers to diagnose and resolve the problem.

Meta's subsequent engineering investigation identified an accidental configuration change affecting its global backbone network as the underlying cause.

IMPORTANT DISTINCTION
The available technical evidence supports an accidental network configuration failure. This investigation does not establish that a cyberattack caused the incident.
AFFECTED SERVICES

Multiple platforms

Facebook, Instagram, WhatsApp and other Meta services were affected.

DATE

October 4, 2021

The incident began at approximately 15:40 UTC according to network observations.

PRIMARY CAUSE

Network configuration

An accidental change disrupted Meta's global backbone network.

RECOVERY

Several hours

Services returned gradually after engineers restored network connectivity.

02 / INCIDENT CHRONOLOGY

The timeline

The following timeline combines Meta's technical account with independent network observations. All times are UTC and approximate.

15:40 — NETWORK CHANGES

Cloudflare observed a major increase in routing changes originating from Facebook's network. Meta later identified the beginning of the incident with a backbone capacity maintenance command.

15:51 — OUTAGE DETECTED

Cloudflare opened an internal incident after observing DNS lookup failures affecting Facebook.

15:58 — DNS ROUTES WITHDRAWN

Cloudflare observed Facebook's DNS prefixes disappearing from global routing tables. External networks could no longer reliably reach Facebook's DNS infrastructure.

DURING THE OUTAGE — RECOVERY WORK

Meta engineers experienced difficulties accessing normal internal tools and network management systems. Engineers were sent onsite to help restore connectivity.

21:00–21:20 — ROUTING RETURNS

Cloudflare observed renewed BGP activity, followed by Facebook DNS becoming available again around 21:20 UTC.

22:45 — BROADER REACHABILITY

ThousandEyes reported that Facebook, Instagram and WhatsApp had been offline globally for more than seven hours, using its broader application-reachability observations.

Timeline note: DNS recovery and full application availability are different measurements. The timestamps above should not be interpreted as meaning every user regained access simultaneously.
03 / TECHNICAL ANALYSIS

Why did it happen?

Meta's global backbone network connects its computing facilities and data centers. During routine maintenance, a command intended to assess available network capacity unintentionally disconnected backbone connections.

Meta explained that a bug in an internal auditing tool prevented the command from being stopped as intended.

Understanding DNS

DNS stands for Domain Name System. It translates readable website names into the IP addresses computers use to connect to services.

Understanding BGP

BGP stands for Border Gateway Protocol. It allows independent networks to exchange routing information about how traffic should reach different destinations.

During the incident, Meta's DNS servers withdrew their BGP advertisements after losing connectivity to the company's data centers. This made those DNS servers unreachable from the wider internet.

04 / VERIFIED FINDINGS

What the evidence establishes

FINDING 001 — Global service disruption

Multiple Meta services became inaccessible across the world on October 4, 2021.

FINDING 002 — Internal configuration failure

Meta attributed the incident to a faulty configuration change affecting its backbone routers.

FINDING 003 — Auditing tool failure

Meta reported that a bug in its internal auditing tool failed to prevent the problematic maintenance command.

FINDING 004 — DNS and BGP consequences

Independent network observations documented route withdrawals and DNS failures during the outage.

FINDING 005 — Difficult recovery

Meta reported that the outage also affected internal tools and network access, requiring engineers to work onsite at data centers.

FINDING 006 — Data security statement

Meta stated that it had no evidence that user data was compromised as a result of the downtime.

FINAL CONCLUSION

An infrastructure failure, not a confirmed attack.

The available evidence supports Meta's explanation of an accidental configuration failure that disrupted its global network.

The incident demonstrates how interconnected infrastructure can create widespread service disruptions when critical network systems fail.

No evidence in the sources reviewed establishes that malicious activity caused the outage.
