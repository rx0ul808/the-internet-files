THE INTERNET FILES / INVESTIGATION 003

THE FLAW THAT SHOOK THE WEB.

Two critical vulnerabilities. A widely used programming language. An international security response. An investigation into PHP2Shell and the October 2026 security crisis.

CASE 003 CYBERSECURITY OCTOBER 2026 RESEARCH DRAFT
01 / CASE OVERVIEW

WHAT HAPPENED?

On October 21, 2026, the PHP development team released emergency security updates addressing two critical vulnerabilities, identified as CVE-2026-109618 and CVE-2026-109619.

The vulnerabilities became known collectively as PHP2Shell. Under certain conditions, they could allow an unauthenticated attacker to execute code remotely on an affected system.

Security organizations around the world issued warnings and urged administrators to identify vulnerable systems and apply the available updates.

THE CENTRAL QUESTION: How did two vulnerabilities in a widely used programming language trigger an international security response, and what did the incident reveal about the security of the web?

02 / BACKGROUND

THE TECHNOLOGY BEHIND THE INCIDENT.

PHP is a programming language commonly used to build websites and web applications. It can process requests, communicate with databases, and generate content displayed in a browser.

PHP is also used by popular content-management systems and other software. As a result, a vulnerability in PHP can potentially affect many different organizations and services.

VULNERABILITY 01

CVE-2026-109618

An out-of-memory handling vulnerability. Under certain conditions, improper memory handling could lead to remote code execution.

VULNERABILITY 02

CVE-2026-109619

A use-after-free vulnerability involving stale global state. Successful exploitation could also lead to remote code execution.

SEVERITY: Both vulnerabilities were assigned a CVSS 4.0 severity score of 9.2 out of 10 by reporting security organizations.
03 / TIMELINE

HOW THE INCIDENT UNFOLDED.

The following timeline separates early research, public disclosure, security updates, and later reports of exploitation.

AUGUST 11, 2026

Initial vulnerability report

According to security vendor reporting, the PHP team received an initial report concerning the underlying issue.

AUGUST 24, 2026

Additional research

Wiz Research independently reported related findings to the PHP team.

SEPTEMBER 18, 2026

Further attack research submitted

Additional attack vectors were reported during the coordinated vulnerability disclosure process.

OCTOBER 17, 2026

Early exploitation attempt reported

Sophos reported that Amazon Threat Intelligence had identified an exploitation attempt before the public security release.

This is a reported attempt, not proof that a particular system was successfully compromised.

OCTOBER 20, 2026

The vulnerabilities become public

Reports of the vulnerabilities appeared ahead of the coordinated release. The disclosure schedule was moved forward.

OCTOBER 21, 2026

PHP releases emergency security updates

PHP published fixed releases: 8.5.12, 8.4.27, 8.3.36 and 8.2.35.

CISA urged organizations to patch affected installations immediately.

OCTOBER 22, 2026

Security organizations publish guidance

Security vendors and government organizations published further analysis and remediation guidance for affected PHP installations.

OCTOBER 23, 2026

A third related vulnerability is disclosed

PHP published information about CVE-2026-115560. This was a separate vulnerability requiring additional consideration and mitigation.

OCTOBER 26, 2026

CISA adds the two vulnerabilities to its KEV catalog

CISA added CVE-2026-109618 and CVE-2026-109619 to its Known Exploited Vulnerabilities catalog.

OCTOBER 27, 2026

Canadian Cyber Centre updates its alert

Canada's Cyber Centre updated its advisory with information about exploitation reports and the CISA catalog additions.

OCTOBER 29, 2026

Further exploitation reporting

Palo Alto Networks Unit 42 published an update reporting active exploitation targeting internet-exposed PAN-OS management interfaces.

This is a specific vendor-reported finding, not evidence that every vulnerable PHP installation was compromised.

04 / TECHNICAL EXPLANATION

WHY WERE THESE FLAWS SERIOUS?

Both vulnerabilities involved the way PHP handled memory while processing requests. Memory-management errors can create unexpected behavior inside software.

In this incident, researchers demonstrated that the vulnerabilities could potentially allow remote code execution without first authenticating to the affected application.

Remote Code Execution

A security weakness that could allow an attacker to cause a vulnerable system to execute unauthorized code.

Unauthenticated Access

The vulnerabilities did not require an attacker to successfully log in before attempting exploitation under the affected conditions.

EDITORIAL NOTE: This section intentionally explains the security impact at a high level. It does not reproduce exploit instructions or attack code.
05 / THE ROLE OF AI

WHEN AI ENTERED THE INVESTIGATION.

The discovery process also raised questions about artificial intelligence in cybersecurity.

Reporting from security vendors describes the use of AI-assisted research during the discovery and analysis of the vulnerabilities.

This creates a wider question for the security industry: can AI help researchers discover dangerous software weaknesses faster, and how should developers respond as those capabilities improve?

AI can assist security research, but the findings still need human review, independent verification, and responsible disclosure.

06 / VERIFIED FINDINGS

WHAT THE EVIDENCE ESTABLISHES.

01 — Two critical vulnerabilities existed. PHP published security fixes for CVE-2026-109618 and CVE-2026-109619 on October 21, 2026.

02 — Remote code execution was possible. Successful exploitation could allow an unauthenticated attacker to execute code on an affected system.

03 — Emergency updates were available. PHP released fixed versions and government security organizations urged administrators to update.

04 — Exploitation was later reported. CISA added both vulnerabilities to its Known Exploited Vulnerabilities catalog on October 26.

05 — A third related vulnerability appeared. CVE-2026-115560 was disclosed on October 23 and required separate attention.

09 / CONCLUSION

THE SECURITY OF THE WEB IS SHARED.

PHP2Shell demonstrated how a weakness in widely deployed software can become a serious concern for organizations across the internet.

The incident required coordination between software developers, security researchers, technology companies, and government cybersecurity organizations.

The most important lesson is that software security is not a one-time task. Systems require ongoing maintenance, responsible disclosure, and timely security updates.

The full scale of the incident and its long-term consequences require continued verification.
